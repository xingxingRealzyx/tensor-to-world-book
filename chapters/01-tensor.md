# 第01章 把神经网络看成张量程序

## 01.1 先摸清一个块：片、行、列

暂时把“语言”“智能”“语义”放在一旁。桌上有两张表，每张表三行四列，每格装一个数。把两张表叠起来，就是一个形状为 `[2,3,4]` 的张量。方括号依次记录三件事：有几片、每片几行、每行几个格。这里没有需要想象的四维空间；多一根轴，只是多一层“先选哪一个”的索引。

本书画张量块时，**一个小格代表一个数，一整行代表一个位置的向量，本节的一张切片代表一个样本**。下图把两片摊开，是为了让每个数都能被看见。底下的叠片只帮助记住“这两片属于同一个张量”，不是要你隔着立体方块猜被遮住的数字。

![图01-1 两个样本摊开后是两张3×4表。橙色格是X[1,2,3]，读出来是24。](figures/01-tensor-cells.svg)

跟着图做一次寻址。`X[1,2,3]` 的第一个1，让你选第1片；第二个2，让你选这片的第2行；最后的3，让你选该行第3列。索引从0开始，所以它是人类习惯说的“第二片、第三行、第四列”。答案为24。三个索引选择一个数；`X[1,2,:]` 的冒号表示“这一行所有列”，得到 `[21,22,23,24]`；`X[1,:,:]` 则取出整张三行四列的表。

现在再给这些轴命名。把两片理解为同一批里的两句话，片轴叫 `B`；每句话暂时有三个token，行轴叫 `T`；每个token用四个数表示，列轴叫 `D`。于是 `[2,3,4]` 写成 `[B=2,T=3,D=4]`。数字形状没有变，只是知道了每个轴在任务里负责什么。四个通道通常是模型学出来的表示坐标，不能直接假定它们依次是“颜色、大小、情绪、速度”。

接下来不急着跳到五维。先把四维张量的全部48个数摊在纸上，逐一做索引、换轴、广播和归约。真正值得追踪的不是“这是几维空间”，而是**操作前后，哪根轴留下、哪根轴拆开、哪根轴被求和消掉**。掌握这套读法后，视频 `[B,F,C,H_img,W_img]` 只多了一步“选哪一帧”。

## 01.2 四维张量：两个样本、三通道、两行、四列

“四维张量”不是“四个数”。向量 `[7,8,9,10]` 虽然有四个数，却只需要一个下标就能选出元素，它的形状是 `[4]`，只有一根轴。四维张量需要依次回答四个索引问题，形状里有四个轴长。它也不是要求读者想象物理世界里的四维空间：图像数据原本只占二维平面，但把多张图像、每张图的多个通道放在一起，就自然得到四根轴。

本节到01.6节始终使用同一个完整例子。与上一节从1开始的三维表区分开，这里的数从0开始：

```python
X = torch.arange(48).reshape(2, 3, 2, 4)
# 轴顺序：[B, C, H_img, W_img]
# 轴长度：[2, 3, 2, 4]
```

| 轴及位置 | 长度 | 回答的问题 |
| --- | --- | --- |
| B，第0轴 | 2 | 这是批次中的哪个样本？ |
| C，第1轴 | 3 | 这是样本中的哪个通道？ |
| H_img，第2轴 | 2 | 这是空间平面的哪一行？ |
| W_img，第3轴 | 4 | 这是该行的哪一列？ |

`H_img`、`W_img` 表示图像高和宽，避免与后面注意力头数H、权重矩阵W混淆。代码与图中的小写 `b,c,h,w` 则表示某一次具体选中的索引。这里可以把C=3暂时看作三个颜色通道，但图中的整数只是为了检查地址而构造的数值，并非真实照片的像素统计。卷积中间层的通道也常常是学出来的特征，不能总把它们叫作红、绿、蓝。

![图01-2 完整四维张量摊成两组，每组含三张2×4通道切片。全部48个数均可见，黑底47的四个索引是[1,2,1,3]。](figures/01-4d-slices.svg)

先横向读同一组：b=0下面的三张小表分别是c=0、1、2，它们属于同一个样本；再纵向读两组：b=1是另一个样本，也有相同的三个通道。因此，一张2×4表在这个例子里只代表“一个样本的一个通道”，不能再沿用上一节“每片就是一个样本”的解释。张量块的外观相似，轴名才决定每一片的含义。

现在沿四个问题走到47。先选b=1，排除0至23的整个样本；再选c=2，留下40至47这一片；选h=1，留下 `[44,45,46,47]`；最后选w=3，才得到47。这个连续构造的例子还可以直接算地址：

```text
X[b,c,h,w] = b×24 + c×8 + h×4 + w
X[1,2,1,3] = 1×24 + 2×8 + 1×4 + 3 = 47
```

为什么分别乘24、8、4？跨过一个样本要越过三片、每片八个数，共24个；跨过一个通道要越过两行四列，共8个；跨过一行要越过4个。这个公式是本例“从0连续编号、按当前顺序排列”的结果，不是所有张量数值都满足的定律。真实输入的值可以完全不同，四根轴的寻址方法仍然成立。

## 01.3 整数索引会去轴，范围切片可以保轴

找到同一个值，不代表得到同一种形状。把X的一个样本取出来，可以写 `X[1]`，也可以写 `X[1:2]`。二者都包含原来b=1的24个数，但前者用整数选定B，结果不再需要B这根轴；后者取一个长度为1的范围，仍保留B轴。这不是写法偏好，而是会影响下一层接口的区别。

| 表达式 | 结果形状 | 选中什么 |
| --- | --- | --- |
| `X[1]` | `[3,2,4]` | 第1个样本，去掉B轴 |
| `X[1:2]` | `[1,3,2,4]` | 同一个样本，保留B轴 |
| `X[1,2]` | `[2,4]` | 样本1的通道2，即40至47 |
| `X[1,2,1]` | `[4]` | 该通道的第1行，即44至47 |
| `X[1,2,1,3]` | `[]` | 标量47，没有剩余轴 |
| `X[1:2,2:3,1:2,3:4]` | `[1,1,1,1]` | 只有47，但四根轴都保留 |

这里“秩”指张量的轴数，不是矩阵线性代数中的秩。形状 `[]` 的标量张量秩为0；形状 `[1,1,1,1]` 的张量秩为4。二者元素个数都等于1，不能用元素个数判断有几根轴。

还要留意切片后的局部索引。`S=X[1:2]` 的B轴长1，所以应写 `S[0,2,1,3]` 得到47；不能写 `S[1,2,1,3]`，因为S内部没有第1个样本。原样本编号是1，截取结果中的局部编号却从0重新开始。

![图01-3 从完整的两个样本的三个通道逐步缩小范围。整数索引减少轴的数量；长度1的范围切片保留该轴。最后的一个47既可装在标量中，也可装在[1,1,1,1]中。](figures/01-4d-index.svg)

冒号则表示在该轴上保留全部索引。`X[:,2,:,:]` 从两个样本中都取通道2，结果为 `[2,2,4]`：第一个2是B，第二个2是H_img，C已经被整数2选掉。若下游模块期待四维输入，应使用 `X[:,2:3,:,:]`，得到 `[2,1,2,4]`。这时C虽只有一个通道，B仍然有两个样本，并没有把整个例子退化成单张二维表。

这也是图像推理时经常遇到的接口错误：单张图像可能以 `[C,H_img,W_img]` 存储，而批量图像模块期待 `[B,C,H_img,W_img]`。补一根长度1的B轴只是明确“这批有一张图”，不会凭空创造新内容。本书的主体例子使用B=2，就是为了让样本轴的存在及其被误删的后果在纸面上可见。

## 01.4 四根轴换位置：NCHW到NHWC

同一个图像张量可以按不同顺序组织轴。许多接口用NCHW，N相当于本书的B：先样本、再通道、再高、再宽。另一些接口用NHWC：先样本、再高、再宽，最后才列出该像素的通道。我们现在把 `[2,3,2,4]` 换成 `[2,2,4,3]`，但保持每个像素的三个通道仍然来自同一个位置。

```python
Y = X.permute(0, 2, 3, 1)
# 新第0轴用旧第0轴，新第1轴用旧第2轴，依次类推。
# Y[b,h,w,c] == X[b,c,h,w]
```

参数 `(0,2,3,1)` 是“按新顺序列出旧轴编号”，不是把某几个数放到这些位置。原轴顺序是B、C、H_img、W_img，旧轴编号依次是0、1、2、3；现在需要B、H_img、W_img、C，所以取0、2、3、1。

![图01-4 NHWC输出仍保留两个样本和全部48个数，每个像素的三个小格依次是c0、c1、c2。黑底41和47标出对应关系；下表用41识别直接reshape造成的错误。](figures/01-4d-permute.svg)

图中每个w分组内都有三列c0、c1、c2。例如b=1、h=1、w=3这一像素，三个通道按顺序是 `[31,39,47]`：31来自原c=0片，39来自原c=1片，47来自原c=2片。图把三片中同一位置的三个数并排展示；并没有把一片中相邻的三个像素冒充三个通道。

固定追踪的47从 `X[1,2,1,3]` 对应到 `Y[1,1,3,2]`。再跟踪一个非末角元素：`X[1,2,0,1]=41`，换轴后必须有 `Y[1,0,1,2]=41`。完整的索引等式 `Y[b,h,w,c]=X[b,c,h,w]` 比“输出形状正确”强得多，它可以逐格检查数据是否真的遵守新轴名。

直接写 `R=X.reshape(2,2,4,3)` 也得到 `[2,2,4,3]`，却没有执行上述轴对应。本例的X连续存储，reshape按原来0至47的逻辑次序每三个数重新分组。所以 `R[1,0,1,:]=[27,28,29]`，其最后一格是29，不是41。固定末像素 `R[1,1,3,:]` 则是 `[45,46,47]`，并非正确的 `[31,39,47]`。

这里有个值得亲自验算的陷阱：47恰好处在所有轴的末端，正确permute与错误reshape都让它落在末角。因此，**只检查47仍然存在，甚至只检查47的这个新地址，都抓不住本次错误**。再检查41，或检查一个完整像素的通道组，才能发现元素被错误分组。

逻辑换轴也不等于物理复制全部数值。PyTorch的 `permute` 返回轴置换后的视图，其含义可查[官方torch.permute文档](https://docs.pytorch.org/docs/2.14/generated/torch.permute.html)。对于本例，stride记录沿某根轴前进一步时，在底层存储中跨过多少个元素：

| 对象 | 形状与轴顺序 | stride，单位为元素 |
| --- | --- | --- |
| 连续的X | `[2,3,2,4]`，B/C/H_img/W_img | `[24,8,4,1]` |
| `X.permute(0,2,3,1)` | `[2,2,4,3]`，B/H_img/W_img/C | `[24,4,1,8]` |

新Y在通道轴上前进一格，要跨过原来一片的8个元素；这正是为什么同一像素能读到相隔8的31、39、47。这里改变的是访问规则。后续若显式调用 `contiguous()`，才可能为新轴顺序建立连续存储；reshape在不同输入布局下也可能返回视图或产生复制。先判断元素对应是否正确，再讨论是否复制和性能，不能把两件事混为一谈。

## 01.5 四维广播：在正确的轴上加通道偏置

假设有三个可学习偏置 `b=[10,100,1000]`，分别服务通道0、1、2。我们希望两个样本中所有像素的c=0都加10，c=1都加100，c=2都加1000。规则与样本编号、像素行列无关，输出形状也应保持 `[2,3,2,4]`。

```python
b = torch.tensor([10, 100, 1000])
Z = X + b.view(1, 3, 1, 1)
# Z[b_idx,c,h,w] = X[b_idx,c,h,w] + bias[c]
```

注释里的 `b_idx` 是样本索引，`bias` 指上面的三元素偏置，避免与变量名b混淆。把偏置写成 `[1,3,1,1]`，就是显式声明哪根轴有三个不同的值、哪几根轴重复使用同一个值。

| 对齐的轴 | X长度 | 偏置长度 | 每个轴上的规则 |
| --- | --- | --- | --- |
| B | 2 | 1 | 两个样本共享 |
| C | 3 | 3 | 三个通道各用自己的值 |
| H_img | 2 | 1 | 两行共享 |
| W_img | 4 | 1 | 四列共享 |

从图的最后一片读数：40至47全部加1000，变为1040至1047。固定位置满足 `Z[1,2,1,3]=47+1000=1047`。再看同一空间位置、另一个通道：`X[1,0,1,3]=31`，它只能加通道0的10，得到41。这两个输出虽然空间位置相同，使用的偏置不同。

不要省略形状安排后直接写 `X+b`。广播从最右侧对齐，形状 `[3]` 会先与X的W_img轴比较。本例W_img=4，3与4不相等，且都不是1，所以运算直接报错。若换成宽度恰好为3的另一组图像，程序可能运行成功，却把偏置加在列上，仍然不符合“按通道偏置”的目标。**能广播只证明形状兼容，不证明轴的语义相符。**

广播也不意味着把三个偏置学习成48个独立参数。两个样本、两行、四列都复用同一组b；改变图像数量或分辨率，不会改变这三个参数的数量。训练中，多个位置对共享偏置的影响会合并起来更新它。这个共享思想会延续到卷积、逐位置线性层和归一化的可学习缩放与偏置中。

![图01-5 三个通道偏置广播到完整的两个样本的六片，图中列出全部输出。各片标题写明加哪个数，黑底1047对应原47加通道2的偏置1000。](figures/01-4d-broadcast.svg)

## 01.6 四维归约：留下哪些轴，就保留哪种信息

换轴和广播都保留48个输出位置；求平均则要明确合并哪些位置。现在对同一X做两种不同的平均，始终保留B=2，避免不小心把两个独立样本混在一起。

第一种是“每个像素在三个通道上的均值”。固定b、h、w，只让c从0走到2。以固定的b=1、h=1、w=3为例，读取31、39、47，计算 `(31+39+47)/3=39`。每个像素留下一个数，两行四列仍在，输出为 `[2,1,2,4]`。

第二种是“每个通道在整张图上的均值”。固定b、c，让h、w遍历两行四列，共8个位置。对b=1、c=2，读取40至47，总和348，除以8得到43.5。这次三个通道仍在，但空间平面收成1×1，输出为 `[2,3,1,1]`。

在PyTorch中分别写成：

```python
XF = X.float()  # arange默认整数；均值需要浮点或复数输入。
mean_c = XF.mean(dim=1, keepdim=True)       # [2,1,2,4]
mean_hw = XF.mean(dim=(2,3), keepdim=True)  # [2,3,1,1]
```

`keepdim=True` 表示把被归约的轴保留下来，但长度改为1。因此，通道均值39位于 `mean_c[1,0,1,3]`：输出的c=0是一个统计量槽位，不能解释成“只取原通道0”。空间均值43.5位于 `mean_hw[1,2,0,0]`：输出的h=0、w=0也不是选中了原左上角，而是存放整片的平均值。

若写 `keepdim=False`，两种输出分别变成 `[2,2,4]` 和 `[2,3]`。数值没变，轴数却变了。保留长度1的轴，可以清楚地把 `mean_c` 广播回原通道，或把 `mean_hw` 广播回各自的空间平面。例如 `XF-mean_hw` 表示每个样本的每个通道减去自己那一片的均值。直接拿 `[2,3]` 减 `[2,3,2,4]` 不会自动理解这些轴名；广播仍只按形状右对齐。

归约会丢信息。知道一片均值是43.5，无法唯一恢复40至47；很多不同的八个数也有同一个均值。换轴则保留全部元素及其可逆的索引对应。判断一个模块是否还能保留空间细节时，先找它有没有把H_img、W_img归约掉；判断是否混合了样本，则先找B有没有被纳入归约轴。

![图01-6 同一个四维输入的两种归约。上半图在同一像素处汇总三个通道，下半图在同一通道内汇总八个像素；两种结果都保留两个样本。](figures/01-4d-reduce.svg)

下面这段代码把五幅图的关键地址放在一起校验。它只核对本节确定的数值与布局，不是模型训练，也不把这些人造数值说成训练结果。原有的二维、三维训练实验仍保留在本章实训中。

```python
import torch

X = torch.arange(48).reshape(2, 3, 2, 4)
assert X[1, 2, 1, 3].item() == 47
assert X[1].shape == (3, 2, 4)
assert X[1:2].shape == (1, 3, 2, 4)
assert X[1:2, 2:3, 1:2, 3:4].shape == (1, 1, 1, 1)

Y = X.permute(0, 2, 3, 1)
R = X.reshape(2, 2, 4, 3)
assert Y.shape == R.shape == (2, 2, 4, 3)
assert Y[1, 0, 1, 2].item() == 41
assert R[1, 0, 1, 2].item() == 29
assert Y[1, 1, 3].tolist() == [31, 39, 47]
assert X.stride() == (24, 8, 4, 1)
assert Y.stride() == (24, 4, 1, 8)

bias = torch.tensor([10, 100, 1000]).view(1, 3, 1, 1)
Z = X + bias
assert Z.shape == X.shape
assert Z[1, 2, 1, 3].item() == 1047

mean_c = X.float().mean(dim=1, keepdim=True)
mean_hw = X.float().mean(dim=(2, 3), keepdim=True)
assert mean_c.shape == (2, 1, 2, 4)
assert mean_hw.shape == (2, 3, 1, 1)
assert mean_c[1, 0, 1, 3].item() == 39
assert mean_hw[1, 2, 0, 0].item() == 43.5
print("四维索引、换轴、广播、归约检查通过")
```

**四维纸笔练习A。** `X[:,2,1,3]` 的形状和值是什么？怎样取同一组数并保留四根轴？

**答案。** 形状 `[2]`，两个值为 `[23,47]`。写 `X[:,2:3,1:2,3:4]` 得到 `[2,1,1,1]`。B仍有两个样本，另外三根轴长1。

**四维纸笔练习B。** 正确换轴后的 `Y[0,1,2,:]` 是什么？错误reshape的同一位置是什么？

**答案。** 正确值为 `[6,14,22]`，来自原样本0的三个通道在h=1、w=2处的值。错误值为 `[18,19,20]`，只是按原顺序每三个数重新分组的结果。

**四维纸笔练习C。** 广播后 `Z[0,1,0,2]` 等于多少？把B改成20，偏置参数要增加到60个吗？

**答案。** 原值10加通道1的100，得到110。偏置仍只有3个参数；B轴共享它们，样本数增加不等于参数数增加。

**四维纸笔练习D。** 沿C求平均后，样本0、h=0、w=2处是多少？沿H_img、W_img求平均后，样本1、c=0处是多少？

**答案。** 前者把 `[2,10,18]` 平均，得到10；后者把24至31平均，得到27.5。它们分别放在保轴输出的 `[0,0,0,2]` 与 `[1,0,0,0]`。

## 01.7 矩阵乘法：只追一个输出格

下面换一组方便手算的数据。输入X仍然是“位置×通道”，三行四列；权重W有四行两列。目标是为每个位置重新计算两个通道，所以输出Y应该有三行两列。先不背矩阵公式，只盯住输出左上角那个格 `Y[0,0]`。

![图01-7 X第0行与W第0列逐项相乘，再把四个乘积相加，写入Y[0,0]。](figures/01-tensor-matmul.svg)

第一步，从X取第0行：`[1,0,2,-1]`。第二步，从W取第0列：`[1,0,1,-1]`。第三步，按顺序配对相乘，得到 `[1,0,2,1]`。第四步，把这四个数加起来得到4，填入输出第0行第0列。图中的橙色把整个读取范围标出来；其他输入格没有参与这一个输出格的计算。

再向右挪一格，算 `Y[0,1]`。输入仍取X第0行，但W改取第1列 `[0,1,1,0]`，于是结果是 `1×0+0×1+2×1+(-1)×0=2`。整行输出为 `[4,2]`。换成X第1行，仍使用同一个W，就得到 `[1,2]`；第2行得到 `[1,1]`。

```text
X [3,4] @ W [4,2] = Y [3,2]

Y = [[4,2],
     [1,2],
     [1,1]]
```

现在再读“公共维度必须相等”就很具体：X的一行有四个数，W的一列也必须有四个数，才能一一配对。四项求和后，原通道轴D不再出现在输出形状里。输入的行号T与权重的列号F留下来，所以 `[T,D] @ [D,F]` 得到 `[T,F]`。可以用一句话记住：**输出格的位置由外侧两个轴决定，它的数值沿中间那根共同轴累加。**

若增加批次轴，成为 `[B,T,D] @ [D,F]`，对每个样本的表分别做同样的事。W仍只存一份，并不会因为B=32就学习32套W。这个操作只重新组合一行里的通道，完全没有拿第0个token与第1个token的数相加。到注意力章节，我们才会专门沿位置轴混合整行向量。

## 01.8 广播：把同一条小向量用于每一行

线性层通常还加一个偏置。假设 `b=[10,-1]`，它只有两个数，而Y有三行两列。相加时，让每一行都使用同一个b：第一列加10，第二列减1。这就叫广播。

![图01-8 同一条偏置广播到每个位置。虚线表示参数复用，不是复制成三套可训练参数。](figures/01-tensor-broadcast.svg)

从左上角开始看，4加10得到14；右边的2减1得到1。第二行也照做，得到 `[11,1]`；第三行得到 `[11,0]`。广播后的结果与Y同形状。这里没有沿任何轴求和，也没有把三行合成一行，只是给对应列重复应用同一条规则。

这一点会在位置编码、归一化和模态标记里反复出现。例如 `[B,T,D]+[D]` 可以给所有位置加同一组通道偏置；`[B,T,D]+[T,D]` 可以给每个位置加自己的位置向量，并在样本间共享。应从右往左对齐轴，某根轴长度相等或其中一个为1才能广播；轴碰巧可广播，并不证明语义正确。

## 01.9 reshape与transpose：看编号，别只看形状

把六个数按顺序写成两行三列：第一行 `[1,2,3]`，第二行 `[4,5,6]`。现在有两条完全不同的指令，都能产生三行两列。

![图01-9 reshape保持线性读取次序并重新分组；transpose把原来的列变成新的行。](figures/01-tensor-reshape.svg)

`reshape(3,2)` 的指令是：保持逻辑上的线性次序 `1,2,3,4,5,6`，每两个数分成一行。所以结果为 `[[1,2],[3,4],[5,6]]`。`transpose(1,0)` 的指令是：新行号使用旧列号，新列号使用旧行号。所以原第0列 `[1,4]` 变成新第0行，结果为 `[[1,4],[2,5],[3,6]]`。

它们形状相同，数值放的位置却不同。找一个格就能识破：reshape结果的 `[0,1]` 是2；transpose结果的 `[0,1]` 是4。程序只检查“输出是三行两列”，无法发现这种错。第03章拆多头时，我们会给每个通道贴上编号，直接看这个错误怎样把一个token的通道放到另一个token的位置上。

还有一个存储细节：transpose可能只改变访问索引，不立即复制数据；reshape则可能返回视图，也可能为了符合目标布局复制。图中“搬格子”表达的是逻辑上的元素对应关系，不是在声称GPU一定真的搬了一遍内存。先把索引算对，再讨论连续布局与性能。

## 01.10 汇总与归一化：沿哪个轴收拢

求和也有方向。对 `[[1,2,3],[4,5,6]]`，如果每行内部相加，就得到6与15，原来的两行还在，三列收成一列。如果每列内部相加，就得到5、7、9，原来的三列还在，两行收成一行。

![图01-10 同一输入沿不同轴求和，留下的轴不同。长度1的轴用keepdims保留。](figures/01-tensor-reduce.svg)

这就是归一化中 `axis` 或 `dim` 参数的含义。要对每个token的通道求均值，就沿D收拢，而不沿T收拢。用 `keepdims=True` 得到 `[B,T,1]`，随后就能把每行自己的均值广播回该行所有通道。第04章LayerNorm其实就是“沿D汇总，再广播回D”的组合。

softmax也沿指定轴操作。以一行为例，原始分数 `[2,1,0]`，先统一减去最大值2，得到 `[0,-1,-2]`；取指数得到约 `[1,0.3679,0.1353]`；把它们相加得到约1.5032；每格除以该总和，得到 `[0.6652,0.2447,0.0900]`。分数变成了非负、总和为1的权重。减最大值只为计算稳定，不改变最终分配比例。

语言模型的 `[B,T,V]` 沿词表V归一化，回答“这个位置预测哪一个候选token”；注意力的 `[B,H,Tq,Tk]` 沿Tk归一化，回答“这个查询从哪些键位置读取多少”。同样是softmax，格子的含义由轴决定。第03章会把归一化前后的整张矩阵并排画出。

## 01.11 用五种动作读懂后面的网络

从本章到全模态模型，许多复杂名字最终都能拆成下表里的动作。先用手指在图上指出一个输出格，再说清它读了哪里，这比记忆一长串模块名称更容易检验理解。

| 张量动作 | 你在格子图上会看到什么 | 典型用途 |
| --- | --- | --- |
| 索引、切片、查表 | 取出某些格、某些行或某些片 | embedding、取最后一个位置 |
| reshape、transpose | 元素保留，分组或索引轴改变 | 多头拆分、图像patch展平 |
| 矩阵乘法 | 一行与一列配对，共同轴求和 | 线性投影、注意力两次乘法 |
| 逐元素运算与广播 | 对应格计算，小向量重复使用 | 偏置、残差、激活、门控 |
| 汇总、归一化、拼接 | 某根轴收拢、按比例分配或延长 | LayerNorm、softmax、多模态序列 |

这里“图上的数”有两种用途。写了具体小整数的图通常是可手算的教学例子；写了 `p0`、`t2` 或 `d7` 的格子表示索引地址，不能当成真实激活值。后面画64维、4096维的大模型时，只展示少数格并明确省略，避免一幅图塞进几千个小得看不清的数。

训练并不会改变这些算子的定义。它改变的是W、偏置、嵌入表等可学习参数里的数，使输出更符合目标。输入X、临时中间结果与输出Y随样本变化，称为激活；为了生成时复用历史而保留的K/V，称为缓存。三者都画成张量块，但保存时间、是否学习以及内存用途不同。

例如一个 `[4096,4096]` 权重有16,777,216个数，每个数2字节时权重本身占32 MiB。把输入序列从1024加长到2048，不会使这份W变大，却会增加激活与缓存。训练还要保存梯度和优化器状态，不能只拿参数量乘2来估显存。这些预算会在后面用实际轴长再算一遍。

## 01.12 练习与答案要点

**练习1。** 图01-1中 `X[1,1,:]` 是什么？`X[:,0,0]` 是什么？

**答案。** 前者是第1片第1行，`[17,18,19,20]`。后者从两片都取第0行第0列，得到 `[1,13]`。冒号保留了对应索引范围。

**练习2。** 图01-7只把X的第2行改掉，Y的第0行会改变吗？如果改掉W的第0列呢？

**答案。** 只改X第2行不会影响Y第0行，因为线性层逐行工作。改W第0列可能影响Y所有行的第0列，因为所有位置共用W。

**练习3。** `X [2,3,4] @ W [4,5] + b [5]` 得到什么形状？有多少可学习参数？

**答案。** 输出 `[2,3,5]`；W有20个参数，b有5个，共25个。B和T改变时，这个层的参数数目不变。

**练习4。** 图01-9的两个输出同为 `[3,2]`，仅检查shape能检查出转置错误吗？

**答案。** 不能。再检查一个已知索引，例如输出 `[0,1]` 应对应原 `[1,0]`。正确的transpose结果为4，错误reshape结果为2。

**纸面分镜：把一个输出格算到底。** 图01-7一次展示了完整的“行乘列”；下面把同一运算拆成四个连续画面。用纸遮住后面的步骤，每次只核对当前读取的两个格、它们的乘积，以及累计值，就能亲手检查矩阵乘法。

![图01-11 四步始终更新同一个Y[0,0]。共同轴k从0走到3，本次乘积依次为1、0、2、1，累计值依次为1、1、3、4。](figures/01-print-matmul.svg)

先固定输出地址 `[0,0]`，不再移动它。每一步只让共同轴 k 前进一格：第1步读 `X[0,0]` 和 `W[0,0]`，第2步读 `X[0,1]` 和 `W[1,0]`。X 中固定的是行号，W 中固定的是列号；两边一起变化的 k 才是配对轴。

右边的黑底格不是四个不同输出，而是同一个输出格的四次暂存状态。第2步乘积为0，累计值仍为1；第4步遇到两个负数，乘积为正1，因此从3增加到4。最终只有4写进完整的Y，其余三个累计状态是理解计算过程用的中间画面。

纸上按顺序画四步，是为了把依赖关系展示清楚。实际矩阵乘法内核可能并行计算各个乘积，再分组求和；图中并未要求硬件必须用四次串行指令。无论如何组织，算这个输出格时都要合并同样四项。

**练习5。** 用图01-11同样的四步表格改算 `Y[0,1]`。每步乘积与累计值分别是什么？

**答案。** W改读第1列 `[0,1,1,0]`，X仍读第0行 `[1,0,2,-1]`。四个乘积为 `[0,0,2,0]`，从0开始的累计值为 `[0,0,2,2]`，所以 `Y[0,1]=2`。只能换W的列，不能顺便换掉X的行。
